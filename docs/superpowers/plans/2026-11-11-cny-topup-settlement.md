# 人民币充值入账实施计划

**范围：** 用户自填人民币金额，选择支付宝或微信；USDT 的订单、赠额、账本和路由保持原样。不新增套餐，不复用旧易支付入账回调，不配置真实密钥，不发布。

1. 测试并实现独立人民币订单表。金额用分、额度用整数，持久化服务端报价；用用户和提交编号去重。锁订单和用户行，将余额、账本和订单状态放进同一事务。
2. 接入商户文档的原生支付。后端只向固定 HTTPS 网关创建订单；回调验签后核对商户、应用、订单标识、金额，提交后才确认。支付页面跳转只用于展示。未确认的下单结果不得自动重新发起，验签通过的迟到回调仍可匹配原单。
3. 钱包提供独立的人民币入口和状态显示。未配置验收条件时不开放新订单。实付按报价面值，不在首版验收中额外加 5%；不预设人民币赠额、返利或商户净额。
4. 原路全额退款先预留站内余额；单独核对商户退款凭证后才确认。商户文档未说明发起退款接口及退款金额、退款交易号字段，不能拿一个退款状态码直接冲账。未获得确凿失败证明不释放预留。部分退款和强制扣成负数不在首版。
5. 用本地数据库和模拟网关验收；正式开放前必须有已轮换密钥、费率和结算凭证、可核对的退款通路，并跑小额真实下单、支付、入账、原路退款、财务核对及同一提交财务 CI。实扣、手续费、净结算币种缺失时，不将充值总额当成已结算收入或毛利。

## 小额真实验收前的检查

- 网关采用商户文档的原生创建、POST JSON 签名通知。商户需提供两种支付的实际结账域名、失败或超时查单的鉴权说明、退款发起及可识别全额原路退款的凭证。当前仅接受可验证的 HTTPS 支付跳转地址；只有二维码字段的回执不视为已验收。
- 通过结算单确认收单方、净结算币种、费率计算基数、实扣、实际入账及退款手续费。人民币实付在独立订单留存，尚未将其并入财务毛利；待收齐实际凭证后补入财务归集并完成核对。5% 的 USDT 赠额规则保持原样，不自动扩展到人民币，也不添加 5% 人民币附加费。
- 试验仅使用验收账号。`ZTAPI_CNY_TOPUP_ENABLED` 默认关闭；先在独立测试实例配置 `ZTAPI_CNY_TOPUP_TEST_USER_ID`、`ZTAPI_CNY_TOPUP_MIN_CNY`、`ZTAPI_CNY_TOPUP_MAX_CNY` 和经确认的 `ZTAPI_CNY_TOPUP_CNY_PER_U`，不要设置 `ZTAPI_CNY_TOPUP_PUBLIC=true`。网关的商户、应用、轮换密钥、支付域名及回调站点由服务端配置，禁止提交凭据。关停新单后保留原回调配置，以便核销在途支付。
- 对照同一商户订单验证用户实付、回调金额、到账 U、重复通知无二次入账。收银台跳回页面不触发入账。未确认下单不得反复向商户发起新的同一订单；先在商户后台查清。
- 原路退款前由管理员二次验证并调用 `POST /api/admin/payments/cny/:order_no/refund/hold`，读回待退款状态和额度预留，再在商户后台实际操作。随后从支付方凭证核对原交易号、退款交易号、全额退款金额和原路最终状态，调用同路径 `/confirm`。未经核验的通知不扣减或恢复余额。当前无自动退款和失败后自动解除预留，需按商户最终结果复核。
- 任一真实测试失败、未确认退款、账务不一致或财务 CI 不通过，继续关闭公开入口；USDT 不需要随之下线。
