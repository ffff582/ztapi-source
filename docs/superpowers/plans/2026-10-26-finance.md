# ZTAPI Finance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add independent, evidence-backed monthly gross-profit reporting to the management backend without restarting the main API.

**Architecture:** A small Go reporting process reads production records using SELECT-only credentials and stores financial annotations separately. Existing administrator authentication and finance permissions protect it. The management UI calls a dedicated Nginx-routed prefix.

**Tech Stack:** Go, GORM, existing decimal/JWT libraries, SQLite annotation storage, React, existing Bun/Vitest toolchain.

**Spec:** `docs/superpowers/specs/2026-10-26-finance-design.md`

## Global Constraints

- No customer wallet, pricing, routing or historical settlement writes.
- No main API restart and no paid model calls.
- Calendar months in Asia/Shanghai; original currencies and explicit conversion retained.
- Unknown actual revenue/cost means pending profit, never fabricated zero.
- Use existing JSON wrappers, explicit permissions and immutable financial audit metadata.

## Review Focus

- Fully reserved requests with no settlement ledger delta still recognize revenue once.
- Unknown historical manual/opening funds cannot silently become income or gifts.
- Refund/retry and repeated cost submissions cannot double-count money.
- Mixed currencies and partial/current-month statements cannot produce confirmed profit.
- A revoked administrator, support employee or normal user must not access finance data.

**Interfaces:** `Calculate(Snapshot, Facts, month, now) (Report, error)` consumes bounded immutable source rows and financial metadata. Produces monthly metrics, receipts, channel usage and explicit blockers.
